## Root cause of Smart App Control block

The installer (and every other PE) shipped **completely unsigned**, so Windows has no cryptographic publisher identity to verify — Smart App Control blocks unverified-publisher apps by design. This is not a bug in Windows or in the app; it is the expected consequence of distributing an unsigned commercial installer. The `_2` suffix in the reported filename (`...1.0.0_2.exe`) is a download-side rename: the GitHub release has exactly one asset with the canonical name `MERQO-Retail-Suite-Setup-1.0.0.exe` (verified via API), and CI now cleans the build directory and **fails the build** if the canonical name is ever not produced exactly.

## Signing solution selected

**Route selected for MERQO: OV (Organization Validated) code-signing certificate with the private key in MERQO's own Azure Key Vault, signed from CI via AzureSignTool.**

Why (verified against current Microsoft documentation, 2026):
- **Azure Artifact Signing** (formerly Trusted Signing; Microsoft's recommended service, ~$9.99/month): **not eligible** — current GA restricts organizations to **USA, Canada, EU, UK** (individuals: USA/Canada only). MERQO operates from Bangladesh → cannot onboard. Should MERQO ever establish a legal entity in those regions, this becomes the first choice, and the pipeline supports it (electron-builder native `azureSignOptions`).
- **OV certificate + Azure Key Vault (selected):** available worldwide including Bangladesh; publisher displays MERQO's legal name; no USB token; CI-friendly (AzureSignTool with Entra-ID service principal); SHA-256 + RFC-3161 timestamp; fully compatible with Smart App Control and SmartScreen (reputation builds over time).
- **CA cloud-signing services** (SSL.com eSigner, DigiCert KeyLocker, Certum Cloud): viable alternative if Key Vault is not preferred; the sign hook has a clean extension point for these.
- **Microsoft Store:** re-signs on submission, interesting later; changes the distribution model — deferred.
- **EV certificates:** no longer grant instant SmartScreen bypass (since 2024) — not worth the premium.
- **Self-signed/test certificates:** excluded by policy (and by the task constraints) — they do not help Smart App Control at all.

> Note on PFX: since the CA/Browser Forum baseline requirement (2023), publicly trusted code-signing private keys must live in certified hardware/cloud HSMs — plain exportable `.pfx` files are generally no longer issued. A legacy PFX path exists in the hook for completeness/testing, but production is the Key-Vault route.
